# 旅遊指南專案 — 完整對話紀錄與系統架構技術指南

本文件匯整本專案的所有開發歷史對話核心重點、系統架構決策、常見問答（FAQ）、最新功能規範（多行程排序、天數重編、手機端觸控與版面修正）與跨裝置/跨電腦維護指南，方便您在任何裝置上查閱與無縫接續維護。

## 一、 系統架構解密：網頁託管 vs 即時資料庫

本系統採用現代 Web 經典的**「前後端分離 + 雲端即時無伺服器（Serverless）」**架構，由兩個獨立運作的核心部分組成：

| 零件名稱 | 角色與技術 | 負責工作 | 儲存位置 | 限制與計費 |
| :--- | :--- | :--- | :--- | :--- |
| **零件 A：前端外殼** | 純靜態網頁 (`index.html` + `notion_data.js`) | 負責繪製網頁按鈕、版面排版、深淺色切換、輸入彈窗、拖曳排序、離線快取 | 可自由放置於 Netlify / Cloudflare Pages / GitHub Pages / Firebase Hosting | 純 HTML 大小約 220 KB，幾乎不佔空間，隨開即用。 |
| **零件 B：雲端大腦** | Google Firebase Realtime Database | 負責**即時雙向連線**，電腦或手機修改的景點、日程、天數、照片秒級同步給所有裝置 | 位於 Google Firebase 雲端伺服器（`travelluke-0001`） | 免費額度 1 GB（純文字與壓縮照片足以容納 15,000~20,000 筆）。 |

> [!IMPORTANT]
> **黃金最佳配置（推薦）**：
> * **網頁託管空間**：推薦放置於 **Netlify** 或 **Cloudflare Pages**（完全免費、無儲存空間壓力、支援網頁直接拖曳資料夾秒級更新）。
> * **即時資料庫**：繼續保留 **Firebase Realtime Database**（免費提供全自動即時雙向同步與照片跨裝置展示）。

## 二、 最新功能歷程與重大對話精華

### 1. 多分頁目的地管理 (Multi-Trip Tabs)
* **分頁順序調整**：
  - 支援桌面端滑鼠拖曳與手機端長按拖曳移動順序（HTML5 Drag & Drop + Mobile Touch 模擬）。
  - 在分頁重新命名彈窗中，亦貼心提供「⬅️ 往前移一位 / ➡️ 往後移一位」點擊按鈕。
* **自訂旅遊天數手動輸入**：
  - 新增旅遊目的地分頁時，天數設定改為「手動輸入天數（數字）」，不再受限於固定天數下拉選單。
* **豐富 Emoji 圖示庫**：
  - 內建各大洲分類圖示（亞洲 ⛩️、歐洲 🏰、美洲 🗽、大洋洲/紐澳 🦘🐨🥝、非洲與中東 🦒🐪🏜️🕌、渡假主題 🏖️🏕️🚢🚗 等）。
  - 支援使用者自訂輸入任意 Emoji 字元。

---

### 2. 每日行程 Day 排序與自動序號重新計算
* **天數自由移動**：
  - 每日行程上方的 Day 按鈕支援滑鼠拖曳與手機觸控長按拖曳移動前後順序。
  - 亦可雙擊或點擊 ✏️ 鉛筆圖示，彈窗手動修改名稱與順位。
* **自動遞移重編邏輯（Renumbering）**：
  - 當把某一天的順序調整時（例如將 Day 2 往前拉至 Day 1），系統會自動依照新順序將原本的 Day 數字重新連鎖計算（例如原本的 Day 2 變成 Day 1，而原本的 Day 1 自動遞移為 Day 2，以此類推）。
  - 關聯行程資料庫中的 `Day` 欄位與空白自訂天數清單會同步全自動更新，資料零錯位。

### 3. 手機版 iOS Safari 視窗向上偏移卡死修正
* **問題現象**：
  - 在 iPhone (iOS Safari) 點擊輸入框或搜尋框後，軟鍵盤彈出或收起時，整個網頁視窗會向上偏移一段距離，導致最上方的漢堡選單與按鈕完全無法點擊。
* **修正機制**：
  - **防止字級自動縮放**：將行動端所有 `input, select, textarea` 字級強制鎖定在 `16px` 以上，防止 iOS Safari 自動鏡頭放大。
  - **全域視窗歸位糾偏**：監聽 `focusout`、`scroll` 與 `orientationchange` 事件，當輸入框失去焦點或畫面被非預期捲動時，自動呼叫 `window.scrollTo(0, 0)` 將視窗拉回頂部安全區域。

---

### 4. 手機版漢堡選單右側點擊即時收合
* **遮罩層（Backdrop Overlay）設計**：
  - 當漢堡選單展開時，畫面右側自動覆蓋半透明遮罩層（`#sidebar-overlay`，具備毛玻璃效果與全覆蓋攔截）。
  - 使用者點擊右側任意空白區域（支援 `click`, `touchstart`, `touchend`, `pointerdown`），側邊欄立即平滑向左滑出收合。
  - 點選側邊欄內的任何導航功能（觀光景點管理、每日行程安排、特定 Day 篩選），選單亦會在 60ms 後自動優雅收合。

### 5. 手機版收合後重新開啟「資料空白」徹底解決 (Webkit Reflow Bug)
* **問題現象**：
  - 手機點擊右側收合後，再次按 ☰ 漢堡按鈕開啟選單，側邊欄中的項目文字（如「觀光景點管理」、「Day 1 (10 項)」、「匯出備份」等）全部消失，只剩下單獨的 Emoji 圖示。
* **根本原因剖析**：
  1. **桌面收合樣式洩漏**：桌面端收合時會套用 `aside.sidebar.collapsed { width: 0 !important; }`。先前行動端媒體查詢未覆蓋收合寬度，導致手機收合時側邊欄抽屜被擠壓為 `0px`，內部彈性容器子文字（`.label`）的計算寬度因此一併塌陷為 `0px`。
  2. **WebKit 合成層未觸發重排 (Reflow)**：側邊欄滑入時依賴 GPU 合成層變形 `transform: translateX(0)`。iOS Safari 在硬體變形時不會重新計算文字佈局，使得內部文字維持了寬度為 0 的快取。
  3. **彈性容器排版衝突**：先前在 `.nav-item` 彈性父容器上定義了 `text-overflow: ellipsis; overflow: hidden;`，誤裁切子文字節點。
* **完整修復方案**：
  - **行動端抽屜固定寬度**：在 `@media (max-width: 900px)` 下，將 `aside.sidebar.collapsed` 強制鎖定為 `width: min(315px, 82vw) !important; min-width: min(315px, 82vw) !important;`。手機端收合與展開純靠 `transform: translateX(-100%)` 與 `translateX(0)`，抽屜寬度永不歸零。
  - **淨化 Flex 容器**：移除 `.nav-item` 上的裁切樣式，並設定 `.label` 為 `flex: 1 1 auto; min-width: 0; display: block;`。
  - **強制重排保證**：在 `openSidebar()` 加入 `void sb.offsetHeight;`，確保 WebKit 每次開啟皆即時重新繪製所有文字。

## 三、 常見問答精華收錄 (FAQ)

### Q1：增加分頁、增加觀光景點、增加 Day 數是否有數量限制？
* **答案：架構上完全沒有硬性數量限制！**
  - **資料結構**：系統採用 JavaScript 動態陣列（Array），不論新增 5 個、50 個分頁，或 500 個景點，都可以正常存取與搜尋。
  - **容量極限**：
    1. **本機快取（localStorage）**：上限約為 5 MB。純文字資料可儲存數萬筆；照片因已經過前端 Canvas 自動等比例縮圖（900x600, 82% 品質壓縮），單張約 50~100 KB，容納數百張景點照片綽綽有餘。
    2. **雲端資料庫（Firebase）**：免費額度達 1 GB（1,000 MB），是本機快取的 200 倍以上，足夠數年的旅遊規劃使用。

---

### Q2：換到另一台電腦更新程式，要移走哪些檔案？JSON 還需要嗎？
* **只需要兩個檔案**：
  1. `index.html`（所有介面設計、排版樣式與 JS 邏輯都在裡面）
  2. `notion_data.js`（原始預設景點與行程的離線備份種子資料）
* **JSON 檔已經不需要隨身攜帶**：
  因為所有資料都已經即時存放在 Google Firebase 雲端。JSON 檔案僅是點擊「📥 匯出備份 (JSON)」時產生的離線備份檔案，刪除或不搬移完全不影響網站運作。

---

### Q3：上傳的景點圖片是存放在哪裡？
1. **本機瀏覽器暫存（localStorage）**：供目前電腦或手機秒開與離線瀏覽。
2. **Firebase Realtime Database**：
   - 程式在選擇照片時，會透過 HTML5 Canvas 於瀏覽器端即時等比例壓縮至 900x600 像素，並轉為 **Base64 字串**。
   - 該字串會同步上傳至 Firebase 雲端，讓其他裝置（例如您的手機或親友）打開網址時能秒級同步下載並顯示照片。
   - **特別提醒**：上傳圖片**不會**修改電腦裡的 `index.html` 程式碼，也不會佔用 Netlify 的託管空間。

---

### Q4：若 Firebase Hosting 空間滿了，該如何轉移到 Netlify / Cloudflare？
1. 將資料夾內的網頁確認命名為 `index.html`。
2. 開啟 **Netlify Drop**（[app.netlify.com/drop](https://app.netlify.com/drop)）或 **Cloudflare Pages**。
3. 將包含 `index.html` 與 `notion_data.js` 的資料夾直接拖曳進瀏覽器即可部署完成。
4. **即時同步完全不受影響**：因為連線 Firebase 的金鑰與邏輯寫在 `index.html` 內，換了任何網址打開，都會自動連上同一座 Firebase 資料庫同步。

---

### Q5：手機瀏覽時，畫面底部出現的綠色區塊是什麼？如何消除？
* **原因**：那是您從 **LINE App 聊天室直接點開連結時，LINE 自帶的內建瀏覽器工具列**（包含返回 `<`、網址與 `•••`），並非我們網頁的元件。
* **消除方式**：
  1. 點擊該綠色列右下角的 `•••`（更多），選擇 **「以預設瀏覽器開啟」**（在 Safari 或 Chrome 打開），即可享受全螢幕無干擾體驗。
  2. 或在 LINE 瀏覽器中手指稍微向上滑動網頁，該工具列亦會自動收合。

## 四、 重要安全密碼與操作備忘

* **編輯解鎖通行密碼**：`lukeshih.720`
* **安全性防護機制**：
  - 每次重新整理網頁或重新進入網址，預設一律為**「🔒 唯讀模式」**，防止旅途中手機誤觸修改或刪除資料。
  - 唯讀模式下，所有新增、修改、刪除、拖曳排序與上傳按鈕全面隱藏。
  - 底層 JavaScript 函式全面綁定權限檢核（`isEditUnlocked()`），若未解鎖點擊將強制彈出通行密碼輸入視窗。
  - 點擊右上角「🔒 唯讀模式」輸入通行密碼後，即安全切換為「🔓 編輯模式」。
* **深淺色主題切換**：
  - 側邊欄左下方設有獨立太陽/月亮按鈕（☀️ / 🌙），點選可即時切換主題並自動記憶於裝置中。
